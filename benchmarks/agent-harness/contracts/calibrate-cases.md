- Background: `docs/work-orders/T-604.md` describes calibration. It says to "take up to `n` passing trials"; the required sampling is the seeded shuffle below.
- `calibrate(opts)` in `src/analysis/calibrate.ts` takes a new optional option `cases?: Case[]` (the run's cases).
- Whenever a trial is scored (the clean re-score and every fault-injected copy), the scorer's `case` is the entry of `cases` whose `id` equals the trial's `trace.caseId`, passed whole (`expected`, `rubric` and the rest). When `cases` is omitted or has no entry with that id, the scorer gets the minimal case used today, `{ id: trace.caseId, input: <content of the first message> }`, which has no `expected`.
- Unchanged: a scorer that throws or returns `pass: null` is undecided, which is neither a detection nor a false alarm.
- Sampling: the sample is no longer the first `n` passing trials in input order. All trials with `pass === true` are shuffled with the seed and the first `n` (default 20) of the shuffled list are the sample, in that order. This holds even when every trial belongs to a different case.
  - The shuffle is driven by the module's existing `rng(opts.seed ?? 1)`: for `i` from the last index down to 1, swap position `i` with position `floor(r() * (i + 1))`. The same generator instance is then used for fault injection, so the same trials and seed always give the same file.
  - `falseAlarms.n` is the sample size. The pool handed to the injectors stays all passing trials.
- `hone calibrate` (`src/cli/commands/calibrate.ts`) loads the configured cases with the existing `loadCases(config.cases, io.cwd)` from `src/core/config.ts` and passes them to `calibrate`, so a scorer such as `exact` compares against each case's `expected`. When the cases cannot be loaded, the command still runs, with no cases. No new flags; output format and exit codes are unchanged.
