- Background: `docs/work-orders/T-604.md` describes the feature. Only the module `src/analysis/calibrate.ts` is required here; the `hone calibrate` command is out of scope. Two points differ from the work order and are marked below.
- Exports of `src/analysis/calibrate.ts`: `rng`, `FAULTS`, `inferDomain`, `cohenKappa`, `calibrate`.
- `rng(seed: number): () => number` returns a seeded generator of numbers in `[0, 1)`; the same seed gives the same sequence.
- `FAULTS` is an object keyed by domain (`rag`, `qa`, `agent`), each holding the injectors of that domain keyed by fault type, e.g. `FAULTS.rag["unsupported-claim"]`.
- An injector is `(trial: Trial, rng: () => number, pool: Trial[]) => Trial | undefined`. The work order shows two parameters; the required signature has the third, `pool`: the passing trials a fault may borrow material from (it may contain `trial` itself). An injector returns `undefined` when the fault does not apply. Otherwise it returns a copy with the fault applied and `trace.meta.injectedFault` set to the fault type (other `meta` keys kept); the original trial and trace are never mutated.
- `rag` faults (retrieved documents come from the existing `retrievedDocs(trace)` in `src/scorers/rag.ts`):
  - `unsupported-claim`: needs a string `trace.output` and at least one retrieved document. The new output is the old one followed by a space and one extra sentence picked from a fixed list of plausible unsupported sentences.
  - `wrong-citation`: needs a string output with at least one citation marker (`[id]`, the default pattern of the `rag.citations` scorer) and at least two retrieved documents. One marker is rewritten to `[<id of another retrieved document>]`; the rest of the output is unchanged.
- `qa` faults:
  - `answer-swapped`: `trace.output` becomes the output of a pool trial that has a different `trace.caseId` and a string output different from this trial's. No such trial: `undefined`.
  - `negated`: on a string output. If it contains a run of digits, the first run is replaced by that number plus one. Otherwise ` not` is inserted right after the first whole word among `is, are, was, were, does, did, has, have, can, will`. Neither: `undefined`.
- `agent` faults:
  - `verification-removed`: going backwards from just before the last assistant message, take the nearest assistant message with a tool call whose function name matches `/test|verify|check|run|bash|pytest|npm|cargo|make/i` (the name alone decides; arguments are not inspected). The work order's pattern is shorter; this one is required. That assistant message is removed together with every `tool` message answering one of its calls. None: `undefined`.
  - `tool-result-swapped`: the candidates are, for every `tool` message of the trial, each `tool` message with the same `name` and a different `content` in a pool trial with another `id`. No candidate: `undefined`. Otherwise one candidate is picked and that message's `content` is replaced.
  - `premature-done`: the first assistant message that precedes the last assistant message and whose string content contains, as a whole word and ignoring case, one of `done, complete, completed, fixed, finished, implemented, resolved`. The messages are cut after it, its `tool_calls` are dropped, and `trace.output` becomes its content. A claim that occurs only in the final assistant message does not count: `undefined`.
- `inferDomain(trials: Trial[])` returns `"rag"` when any trial has a span of kind `retrieval`, else `"agent"` when any message has tool calls, else `"qa"`.
- `cohenKappa(a: boolean[], b: boolean[]): number` is Cohen's kappa, `(po - pe) / (1 - pe)`. When `pe` is 1 (both raters use a single category) it is `1` if they agree everywhere and `0` otherwise. Empty input gives `0`.
- `calibrate({ trials, scorer, domain, n = 20, seed = 1, labels? }): Promise<CalibrationFile>`, with `CalibrationFile` from `src/tui/screens/calibrate.tsx`:
  - The sample is the first `n` trials with `pass === true`, in input order; the pool is all passing trials.
  - For every fault type of the domain and every sampled trial, the fault is injected with one generator `rng(seed)` shared by the whole call, and with the pool. A trial where it does not apply is skipped. Each faulted trial is scored with the existing `runScorer`, given the faulted trace, its trial index and the case `{ id: trace.caseId, input: <content of the first message> }`; it counts as detected only when `pass === false`.
  - `faults` has one `{ type, injected, detected, rate, lo, hi }` per fault type. `rate`, `lo`, `hi` are the `mean`, `lo`, `hi` of the existing `wilsonCi(detected, injected)` in `src/stats/interval.ts`; with `injected === 0` they are `0`, `0`, `1`.
  - `falseAlarms` is `{ n, flagged, rate }`: the sampled trials scored unchanged, `n` the sample size, `flagged` those with `pass === false`, `rate = flagged / n` (0 for an empty sample).
  - `schemaVersion` is `1`, `judge` is `scorer.name`, `domain` is the given domain.
  - `kappa` is present only when `labels` (trial id to boolean) covers at least one sampled trial: `cohenKappa` of the scorer's clean verdicts (true unless `pass === false`) against the labels, over the labelled sampled trials.
