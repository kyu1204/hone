- Background: `docs/work-orders/T-605.md` describes the signals and their weights. Only the module is required here; the TUI marker and the `hone explain` line it mentions are out of scope. Where this list is more specific than the work order, this list wins.
- New module `src/analysis/branchpoints.ts` exporting `rankBranchPoints`, `topSteps` and `pickSibling`.
- `rankBranchPoints(failed: Trial, sibling?: Trial): { step: number; score: number; reasons: string[] }[]`. `step` is an index into `failed.trace.messages`. Every signal that hits a step adds its weight to that step's `score` and appends its reason string to `reasons`. Signals and exact reason strings:
  - `+3`, `"tool error at this step"`: for each span of `failed.trace.spans` with `kind: "tool"` and a truthy `attrs.error`. The step is the tool-result message (`role: "tool"`) whose `name` equals the span's `name`; the k-th such error span of a name goes to the k-th tool message of that name. A span with no such message adds nothing.
  - `+3`, `"diverges from passing sibling here"` (only with a sibling): call `alignTraces(failed.trace.messages, sibling.trace.messages)` from `src/analysis/diffTrace.ts`. When `divergence` is not `null`, the step is the failed-side index of the first alignment row at or after `divergence` that has a failed-side index; when there is none, the last message of the failed trace.
  - `+2`, `"tool result differs from the passing sibling"` (only with a sibling): for each aligned row where both sides are `role: "tool"` messages with different content, at the failed-side index.
  - `+1`, `"last tool call before the final answer"`: the last assistant message with non-empty `tool_calls` that comes before the last assistant message of the trace. The step is that assistant message, not its tool result.
  - `+1`, `"claims completion with no tool call after it"`: each assistant message without tool calls whose text contains, as a whole word and ignoring case, one of `done`, `complete`, `completed`, `fixed`, `finished`, `implemented`, `resolved`, `verified`, when no later message has tool calls.
  - `-1`, `"early in the trace (prompt edits are a different workflow)"`: applied once to every step that already has at least one signal above and satisfies `step < 0.2 * failed.trace.messages.length`.
- The work order says messages in the first 20% get -1; the required behaviour is that the penalty only lowers steps that already carry a signal. A step with no signal never appears in the result. A step whose score ends at 0 or below stays in the result.
- Without a sibling, no reason string mentions the sibling.
- Order: `score` descending; equal scores are ordered by `step` descending (later step first).
- `topSteps(ranked, n = 3): number[]` takes the ranked list and returns the `step` numbers of the first `n` entries whose `score` is above 0, in ranked order. An empty list gives `[]`.
- `pickSibling(trial: Trial, trials: Trial[]): Trial | undefined` returns the first trial in `trials` that has a different `id`, `pass === true` and the same `trace.caseId` (any target). It returns `undefined` when there is none (it never falls back to another case) and when `trial.pass` is not `false`.
