# T-1101 Python targets for custom agents: params, recorded traces, concurrency

## Goal
A team that built an in-house agent with LangChain or Strands should get it under `hone test` and `hone sharpen` with a wrapper of a few lines. Today the `python` target runs a callable, but nothing a change can alter reaches it, tool calls are only recorded when the author writes spans by hand, and calls run one at a time.

## Design
- `PythonTargetSpec.params?: Record<string, unknown>`: handed to the callable as `ctx.params`. This is what a change alters: the system prompt, the model, a setting.
- The target's version includes its `params` and `env`. Without that, two variants of one module share cached outputs.
- `ctx.from_langchain(messages)`: records what `agent.invoke(...)["messages"]` returns (LangChain and LangGraph message objects, or dicts): every message with its tool calls and tool results, and the token usage from `usage_metadata`. Returns the final answer text.
- `ctx.from_strands(messages, usage=None)`: records a Strands agent's `agent.messages` (content blocks `text`, `toolUse`, `toolResult`) and `result.metrics.accumulated_usage`. Returns the final answer text.
- Both are duck-typed: the bridge imports neither library. Messages are stored in the form the scorers read (`role`, `content`, `tool_calls`, `tool_call_id`, `name`).
- `ctx.usage(..., model=None)`: a model name lets hone price the tokens from its table when the handler gives no cost.
- `PythonTargetSpec.workers?: number` (default 1): calls the bridge serves at once, on threads. Agent calls wait on a model, so a suite finishes several times sooner; a handler that is not thread-safe keeps the default.
