# T-904 Repository hardening

## Goal
A solo-maintained public repo that cannot be broken by a stray push or a compromised Action.

## Design
- Verify the `protect-main` ruleset with `gh api repos/kyu1204/hone/rulesets` (PR required, `check` status required with strict updates, no force push or deletion, rebase/squash only) and record the JSON in `docs/hardening.md`.
- Workflows: top-level `permissions: contents: read` in `ci.yml`; third-party actions pinned to full commit SHAs with a version comment; `concurrency` cancels superseded PR runs.
- `.github/dependabot.yml`: weekly for `github-actions` and `npm` (grouped minor/patch).
- `SECURITY.md` (private reporting via GitHub Security Advisories, supported versions), `CODEOWNERS` (`* @kyu1204`), `.github/PULL_REQUEST_TEMPLATE.md` (checklist: work order id, tests, DCO sign-off), issue templates (bug, feature) with the `hone --version` and config excerpt fields.
- Repository settings via `gh api`: delete branch on merge (already), disable wiki and projects, enable vulnerability alerts and Dependabot security updates, secret scanning and push protection.
- `scripts/check-hardening.ts` reads the live ruleset and settings and prints a pass/fail table; `docs/hardening.md` records the output and date.
