# T-802 Import Inspect, Docent, plugin-eval, Harbor, OTel

## Goal
Bring other tools' results into the hone store so the same analysis, TUI and correction loop apply. Formats follow `docs/compat.md` verbatim.

## Design (`src/io/import/*.ts`, each exporting `import<Kind>(input) -> { cases: Case[]; trials: Trial[] }` with pure functions over parsed JSON, plus a file loader)
- `inspect.ts`: JSON from `inspect log dump`. One trace per `samples[]` entry: `caseId` = `String(sample.id)`, `trial` = `epoch - 1`, `targetId` = `eval.model`, `messages` 1:1 (Inspect messages are OpenAI-shaped; `tool` messages carry `tool_call_id`), `output` = `output.choices[0].message.content` when present, `scores` from the `scores` map (`C` -> 1/pass, `I` -> 0/fail, `P` -> 0.5/null, numbers kept, `pass` = value >= 1 for letters only), `usage` from `output.usage`, `meta.inspect = { task: eval.task, run_id: eval.run_id }`. Tolerant parser: replace bare `NaN`/`Infinity`/`-Infinity` tokens with `null` before `JSON.parse`. Cases: `input` = sample.input (string or messages), `expected` = sample.target.
- `docent.ts`: an exported AgentRun (`{ id, transcripts | transcript_groups, metadata }`) -> one trace: `transcripts[0].messages` (or the first transcript of the first group), `metadata.scores` -> `Score[]` (`scorer` = key, numeric value, pass when boolean given), `metadata.model` -> `meta.model` and `targetId`, `metadata.task_id` -> `caseId` (default run id). Also accepts an array of AgentRuns or `{ agent_runs: [...] }`.
- `pluginEval.ts`: a `claude plugin eval` case directory: `<case>/prompt.md` (or `input.md`/`task.md`) -> `input`; `graders/*.md` with frontmatter `type` (`regex|tool_used|tool_order|file_exists|llm|baseline`), `weight`, `arm`, body = rubric/pattern -> hone `ScorerSpec[]` where free graders map to deterministic scorers (`regex` with `target`, `tool_used`, `tool_order`, `file_exists`) and `llm`/`baseline` map to `llm.rubric` with the body as rubric; returns `{ cases, scorers }` (no trials). Frontmatter parser: `---` block with `key: value` lines only.
- `harbor.ts`: a trial directory: `results.json` (`task_name` -> `caseId`, `agent_info.name` -> `targetId`, `verifier_result.rewards` -> scores with `scorer` = key, `agent_result.n_input_tokens/n_output_tokens` -> usage, `started_at/finished_at`), `agent/trajectory.json` through `io/atif.ts`, `/verifier/reward.txt|json` fallback when `results.json` has no rewards. Also accepts a job directory (every subdirectory with `results.json`).
- `otel.ts`: OTel JSON (`resourceSpans[].scopeSpans[].spans[]` or a bare `spans[]`): reverse the table in `docs/compat.md` section 3: `gen_ai.operation.name` -> span kind (`chat|generate_content|text_completion` -> llm, `execute_tool` -> tool, `retrieval` -> retrieval, `invoke_agent` -> agent, else custom), attributes -> `input`/`output`/`attrs`, `gen_ai.input.messages`/`gen_ai.output.messages` on the root span -> `messages`, `gen_ai.evaluation.result` events -> `Score[]`, `gen_ai.conversation.id` or trace id -> `caseId`, `gen_ai.request.model` -> `targetId`. Attribute names live only in `io/export/otel.ts` (T-803) and this file imports them from there, so T-802 adds the constants file `src/io/otelAttrs.ts` that T-803 reuses.
- `hone import inspect|docent|plugin-eval|harbor|otel <path> [--target id] [--json]`: writes one run per import (`summary.imported = kind`), prints counts; `plugin-eval` instead writes `cases.jsonl` and prints the scorer specs to paste into `hone.config.ts`.
