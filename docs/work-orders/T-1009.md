# T-1009 The diagnosis as a file a proposer can read

## Goal
Whoever writes a change needs to see what fails, with examples. e2e writes `.e2e/results/<test>/trace.md` for a failed test and names it in the terminal; the coding agent reads that page, not the raw report.

## Design
- Every `hone sharpen` run that gets past the gates writes `.hone/sharpen/<id>-diagnosis.md`: the pass rate now, each failure mode with its definition and size, up to three failing cases per mode (input, expected, output, the reasons of the failed scorers; long values cut at 600 characters), what may change (the declared text, the variants, the change files found), and a change file to copy. Only dev cases: a held-out case never appears in it.
- The account names the file under `Why it fails`.
- `hone sharpen --budget 0` tries nothing: it measures, diagnoses, writes the file and stops with `Nothing was tried`. That is the proposer's first step; no extra flag.

## TDD steps
1. `src/correct/sharpen.test.ts`: the file exists, lists the modes and example cases with input, expected and output, contains no held-out case id, and the account names it; with `budget: 0` no candidate is evaluated.
2. `src/cli/commands/sharpen.test.ts`: `--budget 0` prints the path.
