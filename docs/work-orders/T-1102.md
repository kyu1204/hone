# T-1102 Example: an in-house helpdesk agent, in LangChain and in Strands

## Goal
The case most teams have: an internal agent with tools and house rules, and no evaluation cycle. One example shows the whole path, with the same agent in both frameworks.

## Design
`examples/helpdesk-agent/`:
- `helpdesk.py`: the tools as plain functions over in-memory data (employee lookup, identity check, password reset, leave balance, policy search, ticket creation), and the house rules the cases check.
- `langchain_agent.py`, `strands_agent.py`: the same agent in each framework, each exposing `answer(input, ctx)`. The system prompt and the model come from `ctx.params`; the trace is recorded with `ctx.from_langchain` / `ctx.from_strands`.
- `evals/cases.yaml`: 36 cases over six rules that hold for every case of their kind, so a rule learned from some cases carries to the held-out ones: cite the policy id, verify identity before a password reset, look a balance up instead of guessing, open a ticket with the right category and priority, refuse another employee's private data, say so when no policy covers the question.
- Scorers: inline `fn` scorers that read the trace: required tools, forbidden tools, order, what the answer must and must not say. Their reasons name the rule that was broken, because the diagnosis and the rewrites are built from them.
- `hone.config.ts`: targets `langchain` and `strands` (`HONE_AGENT` picks one; both by default, which makes `hone test` a comparison of the two), `sharpen.text` for the system prompt, the model in `params` (`claude-haiku-5-5` by default).
- `pyproject.toml` for `uv sync`; a README with the three commands.
- The starting prompt is one line, as first versions are.

## TDD steps
1. `examples/examples.test.ts`: the config loads; the cases are well-formed and cover the six rules; the scorers pass and fail on hand-written traces for each rule. No model is called in tests.
2. Run for real with an API key (T-1103).
