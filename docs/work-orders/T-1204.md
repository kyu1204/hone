# T-1204 `hone draft`: drafting cases leaves `hone init`

## Goal
T-1203 put drafting cases into `hone init --cases`. It is a job of its own: init runs once to set a project up, drafting runs again whenever the agent changes or the cases are too few, it has its own preconditions (a config, an LLM key) and its own options (`--read`, `--count` meant nothing without `--cases`). The maintainer's call (2026-10-14): a command of its own, `hone draft`, one of the everyday commands, in the order of use: `init`, `draft`, `test`, `sharpen`.

## Design
- `hone draft [--read file]... [--count 20]` does exactly what `hone init --cases` did: same inputs, same `evals/drafted.yaml`, same run and report. No behaviour changes.
- `hone init` loses `--cases`, `--read` and `--count`. No alias: the flag shipped today and nobody depends on it.
- The messages that named `hone init --cases` name `hone draft`: the missing-config error ("run hone init first, then hone draft"), the agent target's note from detection.
- `hone` with no arguments lists `init`, `draft`, `test`, `sharpen`.
- Docs follow: README, `docs/cli.md`, the skill (`SKILL.md`, `references/setup.md`, `references/cases.md`).
