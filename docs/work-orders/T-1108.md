# T-1108 A change can add to the text, and the cycle stacks the additions that help

## Goal
Found in T-1103. Two Codex sessions followed the skill ("one hypothesis per change") and each wrote three or four prompts, every one the old prompt plus one new paragraph. Each fixed one failure mode. A `text` replaces the whole text, so the cycle could not put two of them together: the best single one won, the verdict was "promising", and the sessions had to write a combined prompt by hand and go around again, which costs a second look at the held-out cases. Putting together changes that only help together is the cycle's job.

## Design
- `change(name, { why, add })`: a paragraph added to the text as it is. `text` stays the whole new text. A change has `text` or `add`, not both; either may come with `config`. `add` needs `sharpen.text` in the config, as `text` does.
- Applying an addition: the current text, a blank line, the addition.
- The search:
  1. every change on its own, as before (an addition on the seed text);
  2. from the best candidate so far, each addition it does not contain yet, the one that did best alone first: `<best> + <addition>`. Every stack goes through the sample check. When a stack becomes the best, the remaining additions are tried on it.
  3. only then the config changes on top of a text, the texts from files on a config change, and the rewrites, as before. Additions come first because they cost what the baseline costs; a config change such as a larger model does not.
- A rewrite by the model inherits what its parent contains, so an addition it was written from is not added again.
- The ledger: a candidate lists the additions it contains (`adds`). A winning stack is saved like a winning rewrite, as `<id>-best.txt` and as a change file with the whole text, and the account names the additions it is made of.

## TDD steps
1. `change.test.ts`: `add` is accepted and loaded; `text` together with `add` is an error; an empty `add` is an error.
2. `sharpen.test.ts`: three additions that each fix a third of the cases: each alone, then the stack of all three, proven on the held-out cases with no model; the order of stacking follows what each did alone; an addition that breaks what works is dropped at the sample and the stack goes on without it; additions are stacked before a variant is tried on top; a rewrite does not get its parent's additions added again.
3. Docs: `docs/correction.md`, the skill (`SKILL.md` and `sharpening`), the diagnosis page's example and `sharpen/README.md` from `hone init`.
