# T-1203 `hone explore`: hone writes the cases, runs them and reports

## Goal
e2e's own AI does the QA engineer's first job: it works out what to test, writes the tests and runs them. For an agent that means reading what it is for, writing the cases that check it, running them and saying what broke. Today a person writes every case.

## Design
- `hone explore [--read file]... [--cases 20] [--trials 1] [--json]`.
- It reads what the agent is for: the text the config declares (`sharpen.text.seed`, usually the system prompt), the files given with `--read` (by default a python target's module file), and the cases that already exist (to follow their form and not repeat their ids).
- It asks hone's model for cases in the `agent` grammar (T-1201): the main jobs, the rules the documents state or imply, edge cases, requests it must refuse. Only what the documents support goes into `calls`, `args` and `says`; a rule that is not written down goes into `judge`, in words.
- Malformed cases are dropped with a note. The rest are appended to `evals/explored.yaml` as drafts to review, then run.
- The report: how many cases, which fail and why, grouped by reason, and what to do next (read the file, delete the cases you disagree with, then `hone sharpen`). Needs an LLM key; without one it says so.

## TDD steps
1. `src/correct/explore.test.ts` with a stub model: cases written and run, malformed ones dropped, existing ids not repeated, failures reported by reason.
