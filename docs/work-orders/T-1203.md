# T-1203 `hone init --cases`: hone writes the cases, runs them and reports

## Goal
e2e's own AI does the QA engineer's first job: it works out what to test, writes the tests and runs them. For an agent that means reading what it is for, writing the cases that check it, running them and saying what broke. Today a person writes every case.

No new command (the maintainer's call, 2026-10-14): setting up the cases is part of `hone init`.

## Design
- `hone init --cases [--read file]... [--count 20]`, in a project that has a config.
- It reads what the agent is for: the text the config declares (`sharpen.text.seed`, usually the system prompt), the files given with `--read` (by default a python target's module file and the files next to it that it imports), and the cases that already exist (to follow their form and not repeat their ids).
- It asks hone's model for cases in the `agent` grammar (T-1201): the main jobs, the rules the documents state or imply, edge cases, requests it must refuse. Only what the documents support goes into `calls`, `args` and `says`; a rule that is not written down goes into `judge`, in words.
- Malformed cases are dropped with a note, and so are cases that name a tool the code does not have. The rest are appended to `evals/drafted.yaml` (tagged `drafted`, the rule each checks in `meta.why`) and run once.
- The report: how many cases were drafted, which fail and why, and what to do next: read the file, delete the cases you disagree with, then `hone sharpen`. Needs an LLM key; without one it says so.
