# T-1001 Three-command surface: `init`, `test`, `sharpen`

## Goal
A newcomer sees three commands and knows which one to type. Twenty equal-looking commands with statistics jargon in their summaries is the opposite. Nothing has been released, so no alias and no compatibility shim.

## Design
- `test` replaces `run` as the verb for "evaluate". Only the CLI verb changes; "a run" stays the noun for one execution (`--run <id>`, `runId`, `.hone/runs`). `src/cli/commands/run.ts` keeps its name and exports; `runUsage()` prints `usage: hone test`.
- `ci` and `report` stop being commands and become options of `test`:
  - `hone test --ci [ci options]` is what `hone ci` was (`src/cli.ts` hands the remaining arguments to `ciCommand`; `ciUsage()` prints `usage: hone test --ci`).
  - `hone test --report [path]` writes the HTML report of that run after the table (default `report.html`), using `renderReport`. `src/cli/commands/report.ts` is deleted; `hone export html` stays.
- `usage()` in `src/cli.ts` prints only the everyday commands, in plain words, then how to open the results (`hone`) and how to list everything else (`hone help all`):
  ```
  init      set up: detect the project, write hone.config.ts and example cases
  test      evaluate: run every case, score it, say how far to trust the score
  sharpen   improve: find why cases fail, try changes, re-test, keep what is proven
  ```
  `sharpen` is listed once T-1003 has added it; until then the usage shows `init` and `test`.
- `hone help` equals `hone --help`. `hone help all` prints every other command in three groups with plain summaries: steps that `sharpen` runs (cluster, calibrate, evolve, optimize, ablate, compare, power), looking at results (tui, matrix, explain, diff, fork), other tools (bisect, export, import, serve). All of them stay callable.
- An unknown command prints the short usage on stderr and exits 2, as today.
- Every mention of `hone run`, `hone ci` and `hone report` in README, `docs/` (except `docs/work-orders/`, which records what was built at the time), `examples/`, `skills/`, `benchmarks/` scripts and messages printed by the CLI is updated. `docs/cli.md` is regenerated with the sections: Everyday (init, test, sharpen), Steps, Results, Tools.
