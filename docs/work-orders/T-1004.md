# T-1004 The first five minutes: init, test, sharpen

## Goal
`hone init`, `hone test`, `hone sharpen` work in that order on a fresh project and the README says so in one screen.

## Design
- `hone init`: the generated `hone.config.ts` contains a `sharpen` block for the detected project when there is a text to rewrite, and a commented example otherwise, so `hone sharpen` has something to change without the user reading the docs.
- `examples/qa-fn` gets a prompt-like text and a variant so the three commands can be shown end to end without an API key for the target.
- README: the quick start is the three commands with real captured output; the command reference shrinks to a link to `docs/cli.md`; "Does it actually improve anything?" states who did what in the two studies (which steps hone ran, which decisions a person made).
- `skills/hone/SKILL.md`, `docs/correction.md`, `docs/README.md`, `docs/concepts.md` follow the three-command surface. `CHANGELOG.md` 0.1.0 lists the surface and `sharpen`.

## TDD steps
1. `src/cli/commands/init.test.ts`: the generated config type-checks and has a `sharpen` block or the commented example.
2. `examples/examples.test.ts`: `hone sharpen` on `qa-fn` with a stubbed chat ends with a verdict.
3. Write the docs; `bun scripts/check-links.ts` and the cli-docs staleness test green.
