# T-1005 Proposals as patches from a coding agent

## Goal
Let `hone sharpen` change anything in the project, not only one declared text and a list of variants. In both 2026-10 studies the change that mattered was outside what `evolve` could touch: a retrieval setting in one, the task statement in the other.

## Design
- A third kind of candidate, `patch`: a coding agent (the `process` target presets: Claude Code, Codex, ...) runs in an isolated copy of the project with the diagnosis, the failing cases' summaries and one instruction: make one change that fixes these failures. The copy's `git diff` is the candidate.
- Evaluating a patch: apply it to a fresh copy, load `hone.config.ts` from that copy, then overwrite `cases`, `scorers`, `gates` and `trials` with the original config's, and run with the copy as the working directory. The agent may change the system; it may not change how the system is graded. A patch that touches the case files is rejected before it runs.
- `sharpen.agent?: { command: string[] | preset; allow?: string[]; deny?: string[] }` selects the agent and the paths it may edit. Default deny: the case files, `.hone/`, `.git/`.
- The agent's session runs with the isolation the agent-harness benchmark needed (`benchmarks/agent-harness/bench.ts`): no operator plugins or MCP servers, sandbox without network, no ancestor instruction files, scrubbed environment. That becomes a reusable preset in `src/targets/`.
- Diagnosis by intervention: before proposing, the loop may run one experiment per failure mode that removes a suspected cause (for example adding the missing information to the input) and record whether the failures go away. A cause confirmed this way is passed to the proposer; an unconfirmed one is passed as a guess.
- Winning patch: written to `.hone/sharpen/<id>-best.patch`; `hone sharpen --apply` applies it to the working tree when the tree is clean.

## TDD steps
1. A fake agent script that edits a file deterministically; the patch candidate is captured, evaluated from a copy and enters the ledger.
2. A fake agent that edits the case file is rejected; one that edits the scorers in the config has no effect on scoring.
3. `--apply` on a clean and on a dirty tree.
4. The isolation preset: the probe from the benchmark, as a test that needs no model.
