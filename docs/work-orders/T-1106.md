# T-1106 `hone sharpen --no-rewrites`

## Goal
Let a person, or a coding agent, have exactly their own changes judged. Today the model writes rewrites whenever a key is reachable, and the only way to stop it is to have no key. An agent under test that calls a model needs that key, so "no key" is not an option there (found in T-1103: Codex proposes, hone only judges).

## Design
- `SharpenOptions.rewrites?: boolean` (default true). With `false` the cycle tries the changes from files and the variants, pairs them as before, and never asks the model for a rewrite. The model still names the failure modes: the diagnosis is not a proposal.
- CLI flag `--no-rewrites`; MCP `hone_sharpen` takes `rewrites: false`.
- The account says so in one line, so a reader knows why no rewrite appears: `Rewrites by a model were off: only the changes from files and the variants were tried.` The line about a missing key is not printed for this.
- With nothing else to try (no change file, no variant) the verdict is `nothing to change`, as without a key.
