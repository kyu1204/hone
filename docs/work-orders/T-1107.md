# T-1107 The winner is tried without the config change it was written on

## Goal
Found in T-1103: with a costlier variant in the config (`model: sonnet`), the variant wins the first round, every rewrite is then written and measured on top of it, and the confirmed winner costs 4.7 to 4.9 times the baseline per case. Whether the rewritten prompt needs the larger model at all was never measured; a person had to think of it. The cycle should.

## Design
- After the search and before the held-out check: when the best candidate is a text that was written on top of a config change (a rewrite on a variant), and the same text was never measured without that config change, it is tried once without it, as `<text id> without <config change>`. It goes through the same sample check as any text, against the baseline.
- This one candidate is not counted against `--budget` or `--max-cost`: like the held-out runs it belongs to confirming, and it runs at the baseline's price.
- Choosing the winner is unchanged in kind: the highest pass rate on the dev cases; equal rates go to the cheaper one, and at equal cost to the one that changes less (a text alone before a text with a config change). So the smaller change replaces the winner only when it is as good.
- A change file that carries both a text and a config stays one candidate: its author put them together.
- The saved change file of a winning rewrite keeps the rewrite's own name and reason.

## TDD steps
1. `sharpen.test.ts`: a variant that helps a little wins the first round; the rewrite written on top of it fixes everything and needs no variant: the candidate `rewrite 1 without wide` appears, wins, and is what the held-out check confirms; the saved change file is named after the rewrite.
2. A rewrite that does need the variant: the extra candidate is tried, scores lower, and the pairing stays the winner.
3. Existing expectations of candidate lists gain the extra row where a rewrite sat on a variant.
4. Docs: `docs/correction.md`, the skill reference `sharpening`.
