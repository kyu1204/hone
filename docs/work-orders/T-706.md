# T-706 MCP server

## Goal
Let an agent (Claude Code, Codex, any MCP client) run and read evaluations itself: the self-correction loop over stdio.

## Design (`src/serve/mcp.ts`)
- Newline-delimited JSON-RPC 2.0 over stdin/stdout, MCP protocol version `2025-06-18`: `initialize` (capabilities `{ tools: {} }`, serverInfo `hone`/VERSION), `notifications/initialized` ignored, `ping`, `tools/list`, `tools/call`. Unknown methods -> `-32601`. Logs go to stderr only; stdout carries protocol frames only.
- Tools (names, JSON Schema inputs, what they return as one `text` content block holding JSON):
  - `hone_run` `{ cases?: string[]; targets?: string[]; trials?: number }` -> run summary (`performRun` with `quiet: true`): runId, passAt1, cost, gates.
  - `hone_list_runs` `{ limit?: number }` -> runs with id, createdAt, targets, summary totals.
  - `hone_matrix` `{ run?: string }` -> the matrix command's `--json` output.
  - `hone_compare` `{ a: string; b: string; run?: string }` -> compare `--json`.
  - `hone_explain` `{ trialId: string }` -> the trial JSON plus `forkCandidates` from T-605.
  - `hone_cluster` `{ run?: string; induce?: boolean }` -> the clusters file.
  - `hone_fork` `{ trialId: string; step: number; content: string }` -> forked trial id, verdict change, divergence rows.
  - Tool errors are returned as `isError: true` with the message, never as a protocol error.
- Implemented by calling the existing command functions with a capturing `CommandIo` and `--json`, so there is one code path per feature. `createMcpServer({ cwd, stdin, stdout, stderr })` returns `{ handle(line) , close() }` so tests drive it without a child process; `hone serve mcp` wires process stdio.
