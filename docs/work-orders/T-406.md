# T-406 hone bisect

## Goal
Find the commit that broke a case: binary search over git history, running the plan at each commit in a worktree, deciding with confidence intervals instead of single runs.

## CLI
- `hone bisect --good <rev> --bad <rev> [--case id]... [--target id] [--trials n=5] [--threshold p]`.
- `git rev-list --reverse good..bad` gives candidates. At each probe commit: `git worktree add` a temp dir, load the probe's `hone.config.ts` from there, run the selected cells with the executor, compute passAt1.
- Decision: both endpoints are measured first; `threshold` defaults to the midpoint of their pass rates (a bad endpoint that is not worse ends the search with no regression). A probe is "bad" when its Wilson upper bound is below the threshold, "good" when the lower bound is above it; otherwise it gets more rounds (up to 3) before the point estimate decides.
- Output: first bad commit with subject, passAt1 at good and bad, probe log. `--json` for machines. Worktrees removed on exit.
