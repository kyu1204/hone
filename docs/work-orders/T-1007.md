# T-1007 sharpen: try each variant again on top of a rewrite that became the best

## Goal
Find changes that only help together. In the 2026-10 RAG study neither the deeper retrieval alone (76% against 79%) nor a rewritten prompt alone (+4.7 points, not significant) beat the baseline; together they were the confirmed result, and a person had combined them. T-1003 tries variants only on the unchanged config, so it would never make that combination.

## Design
- In the propose loop of `src/correct/sharpen.ts`, when the best member so far carries a text and no variant, each declared variant not yet tried on that member is tried on top of it before the next rewrite is requested. One candidate per pair, each counted against the budget.
- The candidate: `id` `variant <name> on <parent id>`, `kind: "variant"`, `parent` the rewrite, with the rewrite's `text` and the variant's name. It runs on all dev cases; a variant is cheap to describe and has no sample check.
- The account names what to apply: when the winner carries a variant it adds a line saying which one, next to the line with the new text.

## TDD steps
1. `src/correct/sharpen.test.ts`: a system where the variant helps only once the text is rewritten. The ledger is `variant wide` (no gain), `rewrite 1` (half), `variant wide on rewrite 1` (all); the winner carries both and is proven on the held-out cases; the account names the variant and the text file.
2. The existing combination test (a rewrite landing on a variant) still passes.
