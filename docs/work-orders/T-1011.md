# T-1011 A held-out set wears out: count its use and raise the bar

## Goal
Once changes are files that a person or an agent keeps writing, the same held-out cases judge run after run. Each verdict leaks a little, and the tenth attempt that reaches p < 0.05 is not the same evidence as the first.

## Design
- `.hone/sharpen/holdout.json` records, per split (seed and the hash of the held-out ids), how many confirmations have run on it.
- The final test of a run uses `alpha / n`, where `n` counts this confirmation and the earlier ones on the same split (Bonferroni). The account says so when `n > 1`: how many times the set has judged, the bar now, and that new cases restore it.
- Runs that stop before the confirmation do not count.
