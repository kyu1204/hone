# T-1110 The search runs at the baseline's price

## Goal
Found in T-1103: 69% of what the benchmark spent on the agent under test went to trials on a larger model that the example offers as a variant. It was measured alone, which is what a variant is for. But because it led after the first round, every rewrite of the first two runs was then written and measured on top of it, at three times the price, and the prompt turned out not to need it. T-1107 and T-1109 made the cycle choose the cheaper candidate; this makes it stop paying for the expensive one while it searches.

## Design
- A config change is costly when its own run cost more than 1.1 times the baseline's run on the same cases.
- While searching, the candidate to build on is the best one that carries no costly config change. Stacks, pairings with config changes that are not costly, and rewrites all climb from there.
- When the search is over, each costly config change is put once on top of that candidate (`model: large on rewrite 3`), unless the candidate already passes every case, carries a config change itself, or `--max-cost` is spent. This is outside `--budget`: a variant that was declared gets weighed against the final text.
- Choosing the winner is unchanged (T-1109).
- A project that wants its search on the larger model makes the larger model the baseline.
