# T-1002 Config: one `sharpen` block says what may change

## Goal
The config key a user writes should match the command that uses it. `evolve` and `optimize` are names of internal steps.

## Design
- `HoneConfig.sharpen?: { text?: { seed: string; apply: (config, text) => HoneConfig; label?: string }; variants?: Record<string, (config) => HoneConfig> }` replaces the top-level `evolve` and `optimize` keys. Same shapes, new home.
  - `text`: one text hone may rewrite (a prompt, a rule file, a rubric) and how to put a version of it into the config.
  - `variants`: named alternative configs hone may try (a setting, a model, a retrieval depth).
- `correct/evolve.ts` reads `config.sharpen?.text`, `correct/optimize.ts` reads `config.sharpen?.variants`. Their error messages name the new keys.
- `ablations` stays where it is.
- Configs in `examples/` and `benchmarks/`, and `docs/config.md`, `docs/correction.md` follow.
