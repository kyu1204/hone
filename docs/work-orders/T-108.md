# T-108 resume(prefix) on targets

## Goal
Let fork (T-701) re-run a target from a pinned message prefix instead of from scratch.

## Contract
`Target.resume?(prefix: ChatMessage[], input: unknown, ctx: RunContext): Promise<TargetOutput>`. The executor calls `resume` when `ctx.prefix` is set and the target implements it; otherwise it falls back to `run` with `ctx.prefix` still set, so targets may also read `ctx.prefix` inside `run`.

## Per target
- fn: `resume` calls `fn(input, ctx)` with `ctx.prefix` populated; the recorder seeds `messages` with the prefix so the returned trace starts with it.
- http: `body` template receives `prefix`; default body becomes `{ input, prefix }`. Returned messages are prefixed if the server does not echo them.
- python: `ctx.prefix` is forwarded in the JSON-lines `ctx`.
- mcp and replay: not supported; `resume` is absent (executor falls back to `run`).
- process: approximation. The prompt sent to the agent is `renderPrefix(prefix) + "\n\n" + instruction`, where `renderPrefix` writes each prior turn as `### user` / `### assistant` / `### tool <name>` sections. `meta.resumeMode = "rendered-prefix"` so the UI can label it. Claude Code gets the same treatment in this task; a session-level resume is a later improvement.
