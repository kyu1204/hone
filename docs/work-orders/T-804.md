# T-804 Skill, shipped docs, init opt-in install

## Goal
An agent can learn to use hone from inside the repo: a SKILL.md for Claude Code and Codex, a `docs/` set the package ships, and `hone init --skills` to install the skill.

## Design
- `skills/hone/SKILL.md`: frontmatter `name: hone`, `description` (one line, when to use), body: the correction loop in 8 steps with the exact commands (`hone run`, `hone matrix`, `hone explain <trial>`, `hone cluster --induce`, `hone fork`, `hone evolve`, `hone optimize`, `hone ci`), the MCP tool names from T-706 and how to start `hone serve mcp`, and the rule "never report an improvement without the paired verdict". Under 150 lines.
- `docs/`: `cli.md` (every command, generated from each command's usage string by `scripts/gen-cli-docs.ts` and checked in; the test fails when stale), `config.md` (HoneConfig fields, targets, scorers, gates, ablations, evolve, optimize), `analysis.md` (cluster/taxonomy/calibrate/branchpoints/diff and the JSON contracts), `correction.md` (fork/evolve/optimize/bisect/ablate and how verdicts are decided), `serve.md` (ssh/reward/mcp), `formats.md` (import/export formats, pointing at compat.md). Hand-written, concise, Korean not required (English docs for the public repo).
- `package.json` `files` includes `docs/` and `skills/`; README links to them.
- `hone init --skills` copies `skills/hone/SKILL.md` to `.claude/skills/hone/SKILL.md` (and `.codex/skills/hone/SKILL.md` when a `.codex/` directory exists); never overwrites without `--force`; prints what it installed. The skill file is embedded at build time via Bun text import so the compiled binary carries it.
