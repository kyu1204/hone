# T-1201 A case says what must hold in the agent's conversation

## Goal
e2e gives integration tests a grammar. hone's cases can say what the output must be, but not what an agent must have done: which tool, with which arguments, in which order, and what the answer must and must not say. The helpdesk example needed three scorer functions written by hand for that.

## Design
- A scorer `{ name: "agent" }` reads `case.expected`:
  - `calls`: tools that must be called; `never`: tools that must not be;
  - `order`: tools that must be called in this order;
  - `args`: `{ tool: { argument: value } }`, a call of that tool with these values (compared as text, case ignored);
  - `says`, `never_says`: what the final answer must and must not contain (case ignored);
  - `judge`: a rule in words, or a list of them, decided by hone's model from the conversation. Without a key the trial is undecided, not failed.
- One score per trial: pass when everything holds. The reason names each expectation that does not, because the diagnosis and the rewrites are built from reasons.
- A case without any of these keys is not checked by this scorer.
- The helpdesk example uses it in place of its three hand-written scorers.
