# T-103 Python function target

## Goal
Call a Python function as a Target through a long-lived subprocess speaking JSON lines, so RAG pipelines written in Python need no HTTP wrapper.

## Spec `{ kind: "python", module: string, fn = "handler", python = "python3", cwd?, env?, timeoutMs = 120000 }`
- `module` is a file path (`./rag/app.py`) or a dotted module name when `cwd` is on `PYTHONPATH`.

## Protocol
- hone spawns `python -I <bridge> <module> <fn>` once per Target (`src/targets/python/hone_bridge.py`, shipped in the package `files`). The bridge imports the module, then loops: read one JSON line `{ "id", "input", "ctx": { "caseId", "trial", "prefix" } }` from stdin, call `fn(input, ctx)` (sync or async), write one JSON line `{ "id", "result" }` or `{ "id", "error": { "type", "message", "traceback" } }`.
- `ctx` passed to Python is a `hone_bridge.Context` with `span(kind, name)` context manager (records input/output via `.set_input()/.set_output()`), `message(role, content, **kw)`, `usage(input_tokens=, output_tokens=, cost_usd=)`. The bridge serialises recorded spans/messages/usage into `result` as `{ "output", "messages", "spans", "usage" }` when the function returns a plain value, or merges when it returns such a dict itself.
- A crash or a non-JSON line kills and restarts the subprocess; the in-flight request fails with `TargetOutput.error`. `close()` ends the process.
- `version()`: sha256 of the module file contents when `module` is a path, else of the module name plus `python --version`.
