# T-602 Taxonomy induction and classification

## Goal
Turn clusters into a named failure taxonomy (AdaMAST-style: induced from this system's own traces), persist it, and classify new failures against it with Jev.

## Design (`src/analysis/taxonomy.ts`)
- `induceTaxonomy(clusters, { chat, existing? }) -> FailureCode[]`: for each cluster, one `chat()` call with up to 6 summaries asks for JSON `{ code, axis: "system"|"role"|"domain", definition, evidencePatterns: string[] }` (`code` is kebab-case, 2-4 words). Codes matching an existing one (same code, or Jev `noul` "these two definitions describe the same failure" >= 0.8 when a Jev client is given) keep the existing entry. Result is saved to `.hone/taxonomy.json` as `{ schemaVersion: 1, updatedAt, codes }`.
- `classify(trials, codes, { jev }) -> Map<trialId, { code, confidence }>`: one Jev `choice` per trial over the codes plus `other`, state = summary + last messages; batched by state (one request per trial, 256 questions when several trials share a state is not applicable here, so requests run with the client's concurrency).
- `hone cluster --induce` runs T-601 clustering, then induction, then rewrites `clusters-<runId>.json` with real codes (counts from the classification of every failed trial, not only cluster membership). `hone cluster --classify` classifies the latest run against the saved taxonomy without re-inducing.
