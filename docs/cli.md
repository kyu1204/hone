# CLI reference

Generated by `bun scripts/gen-cli-docs.ts` from each command's `--help`; do not edit by hand.

`hone --help` lists the everyday commands and `hone help all` the rest. Plain `hone` in a terminal opens the dashboard (`hone tui`). Every command accepts `--help`.

## Everyday

### hone init

```
usage: hone init [options]

Detect the project; write hone.config.ts, example cases and a sharpen/ directory; store API keys; install the skill and register the MCP server for coding agents.

  --yes             no prompts; accept detection and skip interactive key entry
  --keys            ask for API keys (default on; --no-keys to skip)
  --force           overwrite an existing hone.config.ts (and an installed skill)
  --agents          install the skill and register the MCP server for coding agents (default on; --no-agents to skip)
  --skills          install only the skill, into a project that already has a config
  --typesafe-key    TYPESAFE_API_KEY to store
  --openrouter-key  OPENROUTER_API_KEY to store
  --anthropic-key   ANTHROPIC_API_KEY to store
  --openai-key      OPENAI_API_KEY to store
```

### hone test

```
usage: hone test [options]
       hone test --ci [gate options]

Run every case against every target, score, and summarise. With --ci: gate per axis for a pipeline (hone test --ci --help).

  --adaptive     keep sampling cells until their confidence interval is narrow
  --cache        use the content-addressed cache (default on; --no-cache to disable)
  --quiet        no per-trial progress on stderr
  --target       only this target id (repeatable, globs ok)
  --case         only this case id (repeatable, globs ok)
  --tag          only cases with this tag (repeatable)
  --json         print the result document instead of the table (or write it to a path)
  --report       also write a self-contained HTML report of this run (default report.html)
  --trials       trials per case x target (default from config, else 3)
  --ci-width     adaptive: stop a cell when its Wilson interval is narrower than this
  --max-trials   adaptive: cap per cell
  --concurrency  parallel trials
  --max-cost     abort when accumulated cost (USD) exceeds this
```

### hone test --ci

```
usage: hone test --ci [options]

Run, check per-axis gates, exit non-zero on the failing axis, leave artifacts.

  --quiet           no per-trial progress
  --cache           use the cache (default on)
  --comment         post a markdown summary as a PR comment (gh) or print it
  --adaptive        adaptive sampling
  --baseline        run id to measure regression against
  --junit           write JUnit XML to this path
  --json            write the gate document to this path (always written to .hone/ci/last.json)
  --target          only this target (repeatable)
  --case            only this case (repeatable)
  --tag             only cases with this tag
  --min-pass-hat-k  k:min, e.g. 3:0.8
  --pr              pull request number for --comment
  --min-pass-at-1   gate on pass@1
  --max-cost        gate on total cost (USD)
  --max-regression  gate on pass@1 drop vs --baseline (paired by case)
  --trials          trials per cell
  --concurrency     parallel trials
```

### hone sharpen

```
usage: hone sharpen [--budget 6] [--max-cost usd] [--until 0.9] [--trials n] [--holdout 0.33] [--seed n] [--no-rewrites] [--no-cache] [--quiet] [--json]

The whole cycle: evaluate, find why cases fail, try changes, re-test them, and confirm the best one on cases no proposal has seen. A change is a file under sharpen/ that calls change(name, { why, text, config }), a variant in config.sharpen.variants, or a rewrite of config.sharpen.text by a model; changes that only help together are paired. Writes .hone/sharpen/<id>.json.

  --json         print the whole result as JSON
  --no-cache     re-run the system instead of using cached outputs
  --no-rewrites  the model writes no rewrite: only the changes from files and the variants are tried
  --quiet        no progress on stderr
  --budget       changes to try (default 6); 0 only measures and writes the diagnosis
  --max-cost     stop trying changes when the spend on the system under test (USD) reaches this
  --until        stop trying changes once this pass rate is reached, e.g. 0.9
  --trials       trials per case
  --holdout      share of the cases kept away from every proposal for the final check (default 0.33)
  --seed         seed of the held-out split
  --alpha        significance level of the final check (default 0.05)
```

## Steps that `hone sharpen` runs for you

### hone cluster

```
usage: hone cluster [--run id] [--k n] [--seed n] [--offline] [--induce | --classify] [--json]

Group the failed trials of a run and write .hone/analysis/clusters-<runId>.json for the clusters screen.

  --json      print the clusters file
  --offline   hashed embeddings even when OPENAI_API_KEY is set
  --induce    name the clusters with the LLM, classify every failure with Jev, save .hone/taxonomy.json
  --classify  classify against the saved taxonomy without inducing
  --run       run id (default: latest)
  --k         number of clusters (default: sqrt(n/2), max 8)
  --seed      k-means seed
```

### hone calibrate

```
usage: hone calibrate --scorer name [--domain rag|qa|agent] [--run id] [--n 20] [--seed n] [--labels file.csv] [--json]

Inject silent faults into passing trials, re-score with one judge, and write .hone/analysis/calibration-<scorer>.json.

  --json    print the calibration file
  --scorer  scorer name from hone.config.ts (required)
  --domain  rag | qa | agent (default: inferred from the traces)
  --run     run id (default: latest)
  --labels  csv of trialId,label (true/false) for kappa
  --n       passing trials to sample (default 20)
  --seed    fault injection seed
```

### hone evolve

```
usage: hone evolve [--budget 6] [--minibatch 8] [--trials n] [--max-cost usd] [--alpha 0.05] [--no-cache] [--json]

Reflect on failures, propose revised text, verify on a minibatch then the full set, and keep the versions no other beats on both pass rate and cost (the text is config.sharpen.text).

  --json       print the result as JSON
  --no-cache   re-run targets instead of using cached outputs
  --budget     candidates to propose (default 6)
  --minibatch  passing cases added to each minibatch (default 8)
  --trials     trials per case
  --max-cost   stop when total spend (USD) reaches this
  --alpha      significance for the final paired verdict (default 0.05)
```

### hone optimize

```
usage: hone optimize [--budget 60] [--batch 10] [--confidence 0.95] [--alpha 0.05] [--min-per-arm 3] [--seed n] [--no-cache] [--json]

Allocate trials across the variants in config.sharpen.variants by Thompson sampling, then decide with a paired test.

  --json         print the result as JSON
  --no-cache     re-run targets instead of using cached outputs
  --budget       total trials to spend (default 60)
  --batch        trials per allocation round (default 10)
  --confidence   stop when P(best) reaches this (default 0.95)
  --alpha        significance for the final paired verdict (default 0.05)
  --min-per-arm  trials every arm gets before stopping early (default 3)
  --seed         Thompson sampling seed
```

### hone ablate

```
usage: hone ablate [name]... [options]

Run the baseline and each named ablation from hone.config.ts, then compare paired.

  --json    print the report as JSON
  --cache   use the cache (default on)
  --quiet   no progress on stderr
  --trials  trials per cell for every run
  --alpha   significance level (default 0.05)
```

### hone compare

```
usage: hone compare <targetA> <targetB> [--run id]
       hone compare --run A --run B [<target>]

Paired comparison per case with significance.

  --json    print the comparison as JSON
  --run     run id (once: compare two targets in it; twice: compare the same target across runs)
  --scorer  compare mean score of this scorer instead of pass rate
  --alpha   significance level (default 0.05)
```

### hone power

```
usage: hone power --effect d [design options]
       hone power --n N

How many cases a paired comparison needs, or the smallest effect N cases can detect.

  --json          print as JSON
  --effect        standardized paired effect to detect (prints required pairs)
  --n             pairs available (prints the minimum detectable effect)
  --alpha         significance level (default 0.05)
  --power         target power (default 0.8)
  --pairing-corr  correlation between the two arms per case (reduces n)
  --repeats       trials per case (reduces the decoding-noise share)
  --noise-share   share of variance that is decoding noise (default 1 with --repeats)
  --icc           intraclass correlation when cases share clusters (with --cluster-size)
  --cluster-size  average cases per cluster
```

## Looking at results

### hone tui

```
usage: hone tui [--run id] [--no-watch] [--read-only]

Open the dashboard over a run. Plain `hone` in a terminal does the same.

  --watch      poll the store every second (default on)
  --read-only  disable fork and edits
  --run        run id (default: latest)
```

### hone matrix

```
usage: hone matrix [--run id] [--by target|model|agent] [--json]

Per-target solve rate, cost, tokens and time per solve, flags, and significance bands.

  --json  print rows as JSON
  --run   run id (default: latest)
  --by    group by target (default), model or agent (from trace.meta)
```

### hone explain

```
usage: hone explain <trialId> [--json] [--width n]

Print one trial: verdict, scores with reasons, messages and spans.
```

### hone diff

```
usage: hone diff <trialA> <trialB> [--json] [--width n]

Align two trajectories step by step and report where they diverge.
```

### hone fork

```
usage: hone fork <trialId> [--step n (--content text | --file path)] [--json]

Replace one message of a trial, re-run the target from that prefix, and compare the verdicts.

  --json     print the forked trial
  --content  replacement text for that message
  --file     read the replacement text from a file
  --step     index of the message to replace (omit to list fork candidates)
```

## Other tools

### hone bisect

```
usage: hone bisect --good <rev> --bad <rev> [options]

Binary-search the commit that broke the selected cases, deciding with confidence intervals.

  --json        print the result as JSON
  --good        a revision where the cases passed
  --bad         a revision where they fail
  --case        only these cases (repeatable, globs ok)
  --target      only these targets (repeatable)
  --trials      trials per case x target per round (default 5)
  --threshold   pass rate below which a commit is bad (default: good rate minus 0.1)
  --max-rounds  extra measurement rounds for unsure probes (default 3)
```

### hone export

```
usage: hone export rollouts [--run id] [--out rollouts.jsonl] [--pass-only] [--reward pass|mean-score|<scorer>] [--format trl|openai]
       hone export otel|docent|junit|html [--run id] [--out path]

Write a run's trials as RL-ready JSONL, OpenTelemetry GenAI spans (OTLP JSON), Docent AgentRuns, JUnit XML, or a self-contained HTML report.

  --pass-only  keep only passing trials (rollouts)
  --run        run id (default: latest)
  --out        output path (default per kind: rollouts.jsonl, otel.json, docent.json, junit.xml, report.html)
  --reward     rollouts: pass (default) | mean-score | <scorer name>
  --format     rollouts: trl (prompt/completion, default) | openai (messages)
```

### hone import

```
usage: hone import claude-code [session.jsonl...] [--project dir] [--limit n] [--since date] [--cases cases.jsonl] [--json]
       hone import inspect|docent|otel <file.json> [--target id] [--cases cases.jsonl] [--json]
       hone import harbor <trial-or-job-dir> [--target id] [--json]
       hone import plugin-eval <case-dir> [--cases cases.jsonl] [--json]

Bring other tools' results into the store: one run per import (plugin-eval yields cases and scorer specs only).

  --json     print the result as JSON
  --project  Claude Code project directory (default ~/.claude/projects/<dashed cwd>)
  --since    only sessions modified on or after this date (claude-code)
  --cases    also write the imported cases to this JSONL path
  --target   target id to record instead of the one in the file
  --limit    newest N sessions (claude-code)
```

### hone serve

```
usage: hone serve ssh [--port 2222] [--host 127.0.0.1] [--run id] [--read-only]
       hone serve reward [--port 8787] [--host 127.0.0.1] [--scorer name]...
       hone serve mcp

ssh serves the dashboard (connect: ssh -p <port> <host>); reward serves the configured scorers over HTTP (GET /health, POST /score, POST /batch); mcp speaks MCP over stdio for agents (tools: hone_test, hone_sharpen, hone_guide, hone_list_runs, hone_matrix, hone_compare, hone_explain, hone_cluster, hone_fork).

ssh options:
  --read-only  disable forks for connected viewers (default on)
  --run        pin a run id instead of following the latest
  --host       bind address (default 127.0.0.1; use 0.0.0.0 to share)
  --port       port (default 2222)
reward options:
  --host    bind address (default 127.0.0.1)
  --scorer  scorer name to serve (repeatable; default all configured)
  --port    port (default 8787)
```

### hone guide

```
usage: hone guide [topic]

Print the skill that `hone init` installs for coding agents, or one topic of it: setup, cases, sharpening, results, steps, mcp.
```
